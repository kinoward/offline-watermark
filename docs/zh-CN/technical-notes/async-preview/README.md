## 项目问题

拖动滑块或连续输入时，JPEG 预览可以在缩小的画布上重画，PDF 却需要异步生成或渲染页面。每次输入都启动一次重任务会积压请求，先开始的任务还可能在新任务之后完成。切换视口布局时，页码和输入状态也需要延续。

## 实现决策

- **按渲染成本调度。** JPEG 把画布重绘排到动画帧，并留出至少 50 毫秒的间隔。PDF 在排版设置停止变化 300 毫秒后再生成预览，一次只运行一个生成任务。选中文件或排版设置变更时增加修订号，只有当前修订的结果可以替换预览。[预览调度](../../../../src/preview.ts)
- **等新预览可用再替换。** PDFium 画布保留上一张图，直到当前请求返回像素。使用浏览器内置阅读器时，先在另一个 iframe 加载下一版，再等待一小段时间才切换，因为 `load` 可能早于首帧绘制。这段时间是项目的经验值。[预览切换](../../../../src/preview.ts) · [画布阅读器](../../../../src/pdf-reader.ts)
- **翻页复用文档，重排复用控件。** PDFium 第一次渲染时接收文档字节，同一文档的后续请求只发送页码和目标尺寸。较小的视图可沿用已有图像，视图变大时再请求更清晰的渲染。跨布局时移动现有输入控件，必要时恢复焦点。[PDF 页面 Worker](../../../../src/pdf-page-worker.ts) · [阅读器调度](../../../../src/pdf-reader.ts) · [编辑器布局](../../../../src/main.ts)

## 验证与边界

浏览器冒烟测试在 1440×900 视口检查 JPEG 改字后的重绘。PDF 场景从 834×1194 触屏视口打开文档，翻到第 2 页，检查输入时旧画布仍可见、后续画布发生变化，并切换到横屏与手机尺寸。放大和关闭预览后，测试核对页码及已输入文字。这些断言覆盖模拟视口里的画布路径，内置 PDF 阅读器的实际首帧时机由浏览器控制。[浏览器预览用例](../../../../tests/browser/smoke.mjs)
