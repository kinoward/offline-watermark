# 本地文件保存与重名处理

**总结日期** 2026-11-19

[技术沉淀目录](../../../../README.zh-CN.md#技术沉淀) · [English](../../../en/technical-notes/local-file-saving/README.md)

## 项目问题

水印成品可能要保存到原文件附近，同时避免碰到原文件和先前的导出件。普通浏览器下载的目标目录由浏览器决定，应用只有取得用户所选目录的句柄后，才能在该目录里检查重名。

## 实现决策

1. **先由用户授予目录访问。** 在安全上下文中检测目录选择器。通过原生选择器打开文件时取得的源文件句柄，用作保存对话框的 `startIn` 提示。用户仍可选其他目录。普通下载通过 Blob URL 和下载链接交给浏览器。[选择器检测与下载实现](../../../../src/file-io.ts) · [保存入口](../../../../src/main.ts)
2. **在所选目录内分配文件名。** 自定义只替换主文件名，沿用源扩展名，且先校验路径字符和保留名。探测时，同名文件和同名目录都视为占用。默认名递增序号直到可用，自定义名冲突时提示改名。[命名和重名判断](../../../../src/file-io.ts)
3. **在失败时限制清理范围。** 创建文件句柄后，在打开写入流前再检查文件是否非空。写入失败时重新取得该名称的句柄，只有仍指向此次打开的同一空文件才尝试移除，并报告写入错误。[写入与清理](../../../../src/file-io.ts)

## 验证与边界

单测用目录句柄替身检查 `startIn`、保留扩展名、文件和目录重名、禁止覆盖原文件的常规路径，以及写入错误后清理空文件。目录 API 的探测、创建和写入是分开的步骤，其他进程可能在其间改变目录。普通下载的最终路径和重名策略由浏览器管理。[文件保存单测](../../../../tests/unit/file-io.test.mjs)
